1. INTRODUCTION

The Campus Event Board is a comprehensive web-based event discovery and registration platform designed to simplify the publication, tracking, and student enrollment processes for university activities. Across large collegiate campuses, traditional methods of circulating notices through bulletin boards, social messaging groups, or paper sign-up sheets lead to information silos, quota mismanagement, missed registration deadlines, and manual clerical effort.

The developed system allows students to browse upcoming departmental events, filter activities across specialized categories (Hackathons, Workshops, Cultural, Technical, Sports, and Seminars), check live seating capacity counters, and instantly register with unique generated digital ticket passes (CIT-EVT-XXXXXX). An administrative dashboard is also provided for faculty coordinators to manage event statuses, alter attendee quotas, and inspect registration rosters.

The application is engineered using HTML5, CSS3, JavaScript, Python 3.11, Flask, and SQLite. To fulfill the DevOps Laboratory syllabus objectives, the software incorporates end-to-end automation across the delivery lifecycle. Git and GitHub govern version control. Jenkins automates the multi-stage CI/CD pipeline. Docker packages the application into the campus-event-ci image. Pytest conducts automated test verification. Ansible orchestrates container deployment on port 5001. A Docker Volume named eventboard_data is mounted to ensure persistent SQLite database storage.

3. ABSTRACT

The Campus Event Board is an end-to-end digital solution designed to modernize how collegiate events, hackathons, and symposiums are published and attended. Traditional campus operations suffer from scattered notices, manual registration rosters, and lack of real-time seat quota visibility. The proposed web system provides an intuitive interface where students discover events, filter by departmental domain, search keywords, and receive verifiable digital passes.

The application is powered by a Python Flask microservice backend backed by SQLite relational storage. To satisfy modern cloud-native engineering standards, the project implements a complete DevOps automation toolchain. Git and GitHub manage version control and branch merging. Jenkins automates the Continuous Integration pipeline. Docker containerizes the application into portable images, Pytest runs automated endpoint assertions, and Ansible configures automated container deployment. Persistent data storage is guaranteed through a dedicated Docker Volume named eventboard_data mounted at /app/data. The complete end-to-end delivery workflow follows:

GitHub → Jenkins CI → Docker Build → Pytest Suite → Ansible Deploy → Docker Container (:5001) → SQLite Volume Persistence

20. ADVANTAGES

  • Elimination of Paper Notice Boards: Centralizes all university hackathons, workshops, and sports events on a single digital portal.
  • Instant Pass Generation: Issues cryptographic ticket codes (CIT-EVT-XXXXXX) immediately upon registration.
  • Capacity Safeguards: Live progress bars and duplicate registration rejections prevent overcrowding and double-booking.
  • Automated Quality Assurance: Pytest suites prevent faulty code releases from reaching container deployments.
  • Consistent Environments: Docker containers eliminate the "works on my machine" dilemma.
  • Persistent State Storage: Dedicated Docker Volume (eventboard_data) guarantees that registrations survive container updates.
  • Hands-Free Releases: Jenkins and Ansible automate the entire build-test-deploy chain.
  • Administrative Efficiency: Live faculty dashboard streamlines attendance tracking and CSV rosters.

21. LIMITATIONS

  • Local Embedded Database: The application uses SQLite, which is optimal for single-node deployments but lacks horizontal multi-master scaling.
  • Authentication Scope: Student registration is credential-based (Roll Number and Email) rather than Single Sign-On (SSO) LDAP integration.
  • Payment Gateway: Free events are fully supported; paid ticketing or fine payments are not integrated.
  • Notification Gateway: Digital passes are saved locally on browser; automated SMS/WhatsApp alerts require third-party API integration.
  • Single Host Execution: Currently orchestrated via Docker Engine rather than distributed Kubernetes clusters.

22. CONCLUSION

The Campus Event Board successfully demonstrates the practical integration of an end-to-end full-stack web application with industry-standard DevOps engineering practices. The platform eliminates manual administrative overhead by enabling students to browse events, track capacity quotas, and receive digital passes through a reactive web interface. The project rigorously addresses all ten core components of the 23IT723 DevOps Laboratory syllabus. Git and GitHub govern version control, branching, and collaboration. Jenkins orchestrates a five-stage declarative CI/CD pipeline that compiles Docker images, runs automated Pytest quality gates, and triggers automated deployment. Docker containerizes the application to guarantee environment parity, while Ansible manages container provisioning idempotently. A dedicated Docker Volume (eventboard_data) guarantees persistent relational storage for SQLite records. The successful pipeline execution proves the real-world viability of:

GitHub → Jenkins CI → Docker Build → Pytest → Ansible → Docker Container (:5001) → SQLite Volume
